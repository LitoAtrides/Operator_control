# Пульт оператора — EQueueBrowser для Windows

Приложение Python/PySide6 с встроенным Qt Chromium. Поддерживает табло вызова,
информационную панель и несколько пультов оператора одновременно в одном окне.
Текущая реализация располагает пульты горизонтально; вкладки не используются.

## Установка и настройка

Рекомендуется Windows 10/11 x64. Распакуйте ZIP поставки в отдельную папку,
измените `config.json` и запустите `EQueueBrowser.exe`. Установленный Python
не требуется. Это переносимая сборка, не MSI-установщик.

```json
{
  "connection": {"protocol": "http", "ip": "192.168.1.10", "port": 8080},
  "mode": "orc",
  "segment": "1",
  "orcNumbers": [1, 2]
}
```

`mode`: `display`, `info` или `orc`. `orcNumbers` задаёт список одновременно
открытых пультов. Для `info` нужен `segment`; номер панели сейчас фиксирован: 1.
Это отдельное Windows-приложение, а не точная копия всех настроек Android TV.

При запуске EXE первым читается `config.json` рядом с ним, даже если ярлык
использует другую рабочую папку. Без внешнего файла используется встроенный
пример конфигурации. Куки и кэш сохраняются в пользовательском AppData,
а не в папке установки и не во временном каталоге распаковки EXE.

EXE не подписан сертификатом Authenticode: Windows SmartScreen может показать
предупреждение. Не отключайте антивирус; сверяйте SHA256 и источник загрузки.
На реальном рабочем ПК нужно проверить доступ к серверу, авторизацию, звук
и удобство расположения пультов. CI не обращается к рабочей информационной системе.

## Windows-сборка

Исходники должны находиться на Windows; виртуальное окружение macOS переносить
нельзя. Версия релиза задаётся в `VERSION`.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/package_windows.py
```

Результат в `release/`: standalone EXE, ZIP с EXE/конфигурацией/документацией,
SHA256SUMS, BUILD_INFO.json и smoke-test.json. PyInstaller работает в onefile-
режиме: при первом запуске EXE распаковывает библиотеки во временную папку.
ZIP содержит тот же EXE, но уже вместе с редактируемой конфигурацией и лицензиями.

В GitHub Actions выберите **Windows release → Run workflow**. Workflow работает
на `windows-2022`, собирает именно checked-out ревизию и загружает артефакт
`windows-x64-release`. Он не создаёт релиз и не тегирует репозиторий автоматически.

Сборка запускает полученный EXE из другой рабочей папки. Проверка открывает два
локальных тестовых пульта, выполняет JavaScript в настоящем Chromium и проверяет
иконку и чтение внешней конфигурации. Только в этом CI-тесте Qt работает offscreen
с отключённым GPU; обычный запуск использует стандартные настройки платформы.
